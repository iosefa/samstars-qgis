SAMStars for QGIS

Individual tree crowns from imagery and lidar rasters. Requires QGIS 4.0 or later. This experimental plugin uses the Processing Toolbox for analysis.

Setup · GPU setup · Segment · Train · Workflow steps · Check dependencies

Set up the engine

  1. Open Plugins → SAMStars → Set up SAMStars.
  2. Click Install engine. Setup detects an installed Python 3.10–3.12 with venv and ensurepip support.
  3. Open Advanced to select Python manually or choose a prepared SAMStars environment and click Use existing environment. The environment is checked before selection. Detailed logs are also under Advanced.

Installation requires internet access and several GB of free space. The installer creates a private environment in the active profile under samstars/engines. QGIS and your base Python are unchanged. Failed installs leave the previous engine selected. Repair engine validates a replacement before selecting it. Remove engine deletes only private environments marked as belonging to this plugin; external environments and older unmarked installs are kept. Keep the base Python installed.

Automatic installation supports Linux x64 (Ubuntu 20.04+) and Apple Silicon macOS 14+, following the SAMStars supported platforms. Other platforms need an existing environment and are untested. Installation defaults to CPU. For a custom environment, follow the SAMStars installation guide. Select it under Advanced → Use existing environment. The environment variable SAMSTARS_PYTHON overrides the saved Python path.

Optional GPU setup

Open Set up SAMStars → GPU setup…. Choose NVIDIA CUDA on Linux x64 or Apple MPS on native Apple Silicon macOS 14+. Click Install GPU engine to build a private environment, or Test selected engine to run a GPU check without installing anything. GPU setup is experimental.

GPU acceleration applies to SAM proposals and SAM training. StarDist refinement stays on CPU in private engines. PyTorch and TensorFlow CUDA packages have conflicting runtime pins, so this installer does not combine them. TensorFlow Metal is not installed either.

NVIDIA setup checks nvidia-smi before downloading. Its CUDA 12.6 profile requires driver 560.35.05+; detected Blackwell-or-newer cards use CUDA 12.8 and require driver 570.124.06+. Update drivers through your operating system if needed. These conservative requirements do not guarantee every GPU architecture works. The final computation test must pass. Setup respects CUDA_VISIBLE_DEVICES and tests the worker's default visible GPU.

The plugin downloads runtime packages into a new environment. It never installs system drivers, changes QGIS packages, enables WSL, or compiles CUDA. Native Windows, Intel macOS, Linux ARM, and AMD/Intel GPUs on Linux do not have an automatic GPU profile. Prepared environments can be selected and tested. WSL is not a tested release target.

Setup checks package consistency, CPU and geospatial operations, and GPU matrix/convolution operations with gradients before selecting the new engine. Failed or canceled setup keeps the previous selection. Repair preserves the GPU profile. To switch back, choose CPU (default) → Install CPU engine, or select a previous environment under Advanced.

After successful setup, choose CUDA or Apple MPS in your Processing tool's Advanced parameters. CPU remains the default. Selecting a device never installs packages. Start with a small scene: a successful GPU check does not validate a complete model or its memory needs.

Prepare the scene

Choose local GDAL-readable imagery, a single-band canopy height model in metres, and single-band first-return density. Imagery needs a projected CRS in metres, north-up orientation, and square pixels. Provide a defined CRS and matching coverage for all rasters. SAMStars aligns CHM and density to imagery; survey offsets still need correction beforehand. Density units and cell size must match training. Apply CHM/density scale and offset to pixel values first. Export web services and subdatasets as GeoTIFFs.

Segment tree crowns

In the Processing Toolbox, run SAMStars → Tree crowns → Segment tree crowns. Select the three scene rasters and a trained model bundle directory containing manifest.json. Choose a new or empty output folder.

The final crowns/crowns.gpkg is loaded into the project and returned as CROWNS. Band choices come from the model. Advanced parameters allow overrides: RGB is a comma-separated list in red, green, blue order, with one-based indices. Blank RGB and zero NIR/texture reuse model settings; zero cannot disable a band stored in the model.

This tool performs alignment, cost construction, seed generation, SAM proposals, and StarDist refinement automatically. Use Workflow steps below to adjust or inspect individual stages.

Train a model

Run SAMStars → Tree crowns → Train a model. Select the three scene rasters, labeled crown polygons, and the SAM ViT-L checkpoint sam_vit_l_0b3195.pth from the official SAM checkpoint list. Use one valid polygon per tree and fully annotate the scene. Crop to the labeled area, because unlabeled pixels are treated as background.

Processing's selected-features option, layer subsets, and unsaved polygon edits are preserved in a temporary GeoPackage. RGB defaults to bands 1,2,3. Advanced parameters expose band choices and the SAM/StarDist epoch counts. The new model folder is returned as MODEL and OUTPUT; supply it to segmentation.

Workflow steps

Open SAMStars → Workflow steps in the Processing Toolbox. Each tool has its own dialog and saves outputs for inspection and reuse. Choose a permanent output folder to keep the results. The first three steps need no model; proposals and refinement use a trained bundle. These tools use existing rasters and do not derive CHM/density from raw point clouds.

1. Align input rasters

Choose a required Reference raster to define the output CRS, extent, resolution, and pixel grid. It must use a projected CRS in metres and north-up square pixels. Then select any of the four optional inputs: Imagery, Canopy height, First-return density, and Intensity. Select at least one.

To use the CHM grid, select the CHM as reference and provide imagery, density, and intensity. The optional CHM input can stay blank: use the original CHM downstream. Selecting it as an input as well produces a separate copy on the same grid. Any suitable single-band or multiband raster can be the reference.

Selected inputs produce img.tif, chm.tif, den.tif, or intensity.tif, and are loaded into QGIS. Every imagery band is preserved in its original order. Outputs are Float32; differing grids use bilinear resampling, and matching grids are copied without interpolation. REFERENCE_RASTER points to the original reference file. Skip alignment if all grids already match. This matches pixel grids and does not fix survey offsets.

2. Build cost surface

Select imagery and CHM on the chosen reference grid, such as the aligned imagery and original reference CHM. Set the relative height-edge, NDVI-gap, and texture weights; available terms are normalized. Under Advanced, choose RGB, NIR, and texture bands to match training. Without NIR, NDVI is omitted. cost.tif is loaded with values from 0 to 1; higher values indicate stronger boundary cues. Later steps require exactly matching grids.

The output folder can contain the input rasters or other results. cost.tif and cost.workflow.json must not already exist; the tool names any conflicting file instead of overwriting it.

3. Generate seed points

Select aligned CHM, density, and cost. Adjust the minimum peak value, minimum canopy height, peak-search radius, Gaussian smoothing, and candidate merge radius. The peak threshold applies to both CHM and density, so density units matter. Advanced includes cost penalty, height splitting, and final thinning. The result is an editable seeds.gpkg. You can save it alongside the inputs and cost surface, provided seeds.gpkg and seeds.workflow.json do not already exist.

Inspect the seeds over the imagery. Move, add, or delete points using QGIS editing tools before proceeding. You can also select a subset for proposals.

4. Generate crown proposals (SAM)

Select imagery and CHM on the reference grid, cost, edited seeds, and model bundle. Selections, filters, and unsaved seed edits are exported. Seeds and costs are used as supplied. RGB bands default to the model settings; Advanced exposes device, prompt batching, and smoothing. CPU is the default; choose CUDA or MPS after GPU setup. Points outside the image are skipped with a log message. Points on missing CHM/cost data must be corrected.

Probability and canopy-index rasters are loaded for inspection. These are proposal rasters; the next step produces polygons. Pass the Proposal records output (proposals/proposal_records.json) to refinement. Keep this folder and its rasters in place, because the records contain their paths.

5. Refine crowns (StarDist)

Select the saved proposal records and the same model bundle. Leave both thresholds at -1 for the model settings, or set both explicitly. Advanced controls window size/overlap, minimum crown area, edge exclusion, and duplicate suppression. Set window size and overlap to 0 to refine whole rasters. This tool always uses CPU and does not rerun SAM.

Invalid outlines from raster boundaries are repaired while preserving each crown's attributes. The result crowns/crowns.gpkg is loaded into QGIS. To compare refinement settings, reuse the same proposals with a new output folder.

Storage and compute

CPU is the default. The device setting controls PyTorch proposals. Private engines run StarDist refinement on CPU, including when GPU proposals are selected. In custom environments, TensorFlow manages refinement acceleration independently in the full workflows; the separate Refine crowns tool explicitly uses CPU in every environment. Start with a small area: large scenes and training can need substantial memory and time.

Cost and seed creation allow existing output folders while protecting their specific result and settings files. Alignment, proposals, refinement, training, and full segmentation require new or empty output folders, separate from their inputs and model bundle. Full segmentation/training removes intermediate files unless Keep intermediate files is checked. Workflow steps retain their outputs and prepared inputs, with requested settings and output paths in cost.workflow.json for costs, seeds.workflow.json for seeds, and workflow.json for other steps. Choose a permanent output folder to retain results beyond the session. Cancel stops the worker and its child processes on Linux/macOS; partial output or temporary files can remain. Use a fresh folder for another run. Prepared-tile batch workflows and resuming are available through the SAMStars Python API.

Check dependencies

Run Check SAMStars dependencies for an HTML report and Processing log. It checks scientific imports and small CPU operations, including compiled StarDist code, CRS transformation, and GeoPackage I/O. It does not download or validate a trained model and does not certify GPU availability. A failed check includes the underlying error; use setup to select or install a working environment.

For No module named venv or missing ensurepip, install your operating system's Python venv support or select a Python installation that provides it. A failed installation never replaces the selected engine.
